LLM routing — the decision behind task 018

OmniRoute is a good tool aimed at a different problem

OmniRoute is a self-hosted gateway for coding agents. It runs at localhost:20128 with an Electron app and a React dashboard, and routes IDE tools — Claude Code, Cursor, Cline, Copilot — through a subscription → API-key → cheap → free fallback chain. That is a genuinely useful thing, and it is not what ThinkBoard needs.

ObjectionDetail
Wrong shapeIt is a localhost proxy for one developer's machine. ThinkBoard needs a server-side adapter in a route handler, serving many users, routing per profile_identities.kind, writing an llm_requests row per call, and queueing a run as status='pending' when quota runs out. No generic router knows about any of that.
ComplianceIts provider list includes “web cookie” providers that ride a user's browser session, and its own free-tier docs note that some providers explicitly prohibit programmatic or third-party-harness use. For a state-owned enterprise that is real exposure — and it is the same unanswered question as D-12.
Operational weightYour own point. An Electron app plus a dashboard is a service to run, monitor and secure, for a product whose premise is a free Supabase tier and a pilot team.

What to do instead

LayerChoiceWhy
Interfacesrc/server/llm/service.ts — complete() / stream(), takes a profileId, never a keyalready in the architecture; one seam, swappable
Provider #1OpenRouter — one hosted endpoint, one key, OpenAI-compatible, many free models, its own model-fallback arrayreplaces the gateway you would otherwise run, with zero infrastructure
Provider #2Groqa separate quota pool. Rotation only helps when the pools are independent
Provider #3the user's own key via Vault, when presentkey_source='user'
Failover≈40 lines in ratelimit.tsit must know about llm_requests and queued runs — a generic router does not

Where OmniRoute is worth using: the development loop. Point Claude Code or Cursor at it while building ThinkBoard — that is exactly what it was made for. Just keep it out of the product.

Still unanswered, and it gates task 018. Most no-card free tiers fund themselves with your prompts. Answer that before picking providers, because it may force a small paid tier — which is a budget decision, not an architecture one, since the adapter already covers it.
