How collaboration connects

one WebSocket per person · one TLS handshake · four kinds of traffic

The socket is for listening, never for writing. Broadcast is unvalidated by design, so if clients could publish state directly you would have a second write path that row-level security does not cover. One write path, one set of policies.

Why not Postgres Changes, the simpler option?

It authorises every event once per subscriber and runs on a single thread to preserve ordering, so throughput scales with how many people are watching rather than with how often you write — and a bigger compute add-on does not help. Supabase now points most use cases at Broadcast instead. Both work for a six-person workspace; only one of them still works later, and the setup cost is one trigger and one policy either way.

Private, promoted, group

the contradiction in the spec, and the one column that resolves it

“Individual is private” and “only the leader writes the group sheet” together mean a member's thinking can never reach the Group Result. The leader cannot read private notes; members cannot write group ones. Promotion is the bridge — and it stays the author's decision, not the leader's.

Private

visible to the author only

Highlight and note on my own layer. Works offline. Never leaves my account until I say so.

layer='individual'
shared_at is null

Promoted

visible to the workspace · still authored by me

I press Share to group. The mark and its note become readable by everyone, with my name on them. I can still edit; the leader can hide but never delete.

shared_at = now()

Group sheet

visible to everyone · written by the leader

The leader marks it directly, imports an already-highlighted PDF, or pulls a promoted note across. This is what the Group Result reads.

layer='group' · leader-only write

Test it by signing in as a second member and asserting both are invisible. This is the only non-additive change in the whole plan.

Offline

a capture mode, not a thinking mode

Build the local-first data layer at task 002, not task 010. If every read and write goes through a local repository from the first highlight, offline mode is just stop syncing and hide the group layer. Added at the end instead, it means rewriting the data layer, the optimistic updates and the error handling at once.

One id, three places

so a note found its way home from any of them

The slug is written into the database row, the markdown anchor and the PDF annotation's name field. Any one of the three can rebuild the link if the others are edited by hand. It is derived from the page, the order and a hash of the text plus the rect, so re-importing the same document twice dedupes instead of duplicating.

The import rule, stated once so it is testable. The HTML comment is the only thing read for identity. Prose between comments can be edited freely and re-imports cleanly. A section with no comment imports as a new, unanchored note rather than being dropped. A deleted comment orphans its note, and the importer says so instead of guessing.
