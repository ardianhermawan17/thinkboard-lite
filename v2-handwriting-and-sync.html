What “text without keypress” means. When the OS recogniser commits handwriting, it writes into the field through the platform's input connection — an input event fires with no preceding keydown. That is the signal this page watches, and it is the same signal ThinkBoard uses to know Tier A is working on a device, so it can stop nagging about the pen.

If nothing happens: on iPad check Settings → Apple Pencil → Scribble is on, and that you are using a Pencil rather than a finger — Scribble is Pencil-only. On Android you need 14 or higher, a compatible stylus, and a keyboard that supports the stylus handwriting APIs. On desktop with a mouse, nothing will happen, and that is correct.

02

Three tiers, reordered

v1 had the LLM tier as the default — that was wrong

The v1 plan treated handwriting as a recognition problem to solve in-app, with a vision model as the default transcriber. That made the feature depend on the network, on a free-tier quota, and on sending a person's handwriting to a third party. All three are avoidable.

TIER A · DEFAULT

OS stylus → text

Pen writes into a real text field. iPadOS Scribble, Android 14 platform stylus writing, Samsung DirectWriting. ThinkBoard receives an ordinary change event with real text.

No tier stores an image. Tier A stores text. Tiers B and C store vector strokes — which scale to any zoom, re-render crisply, and can still be transcribed months later. A PNG can do none of those. Your “if possible, not as image or canvas” goal is met in every path, and in the default path nothing is ever captured as ink at all.

03

Four ways to silently break Tier A

each one looks fine in review and fails on the device
Do notBecauseInstead
Use contenteditable or a rich-text editor — Tiptap, Slate, ProseMirror, Lexical The platform recognisers target standard text input fields. A custom editor is not one, and on the web there is no hook to declare yourself as one. A plain <textarea>. A note is 2,000 characters; it did not need ProseMirror anyway.
Let the Konva Stage sit under or over the note field Android's own guidance names “text entry fields overlaying a drawing surface” as needing custom work. The Stage swallows the pen event and the OS never sees a writing gesture. Own stacking context, opaque background, and pointer-events:none on the Stage while the sheet is open.
Put buttons hard against the field's edge Handwriting initiation reserves roughly 40 dp above and below the field and 10 dp either side. A control inside that band steals the first stroke. ~16 px of clear, non-interactive padding all round. The test pad above has exactly that.
Mount the textarea lazily on tap The pen has to land on a field that already exists and can take focus. Render it. Let the pen initiate.

Three of these were already right in v1 for weaker reasons. The textarea was chosen over Tiptap on prompt-budget grounds. Now it is an invariant with a real failure mode behind it — which is the difference between a preference the next agent quietly overrides and a rule in the verify script.

04

The honest problem

the one thing that could sink Tier A

Scribble recognises English, Cantonese, Chinese, French, German, Italian, Japanese, Spanish and Portuguese. Bahasa Indonesia is not on that list.

Indonesian is Latin script, so an English recogniser gets the letters mostly right but biases toward English vocabulary — and the errors will cluster on exactly the domain words that matter. Reported accuracy on supported languages is around 90–95%; Bahasa will sit below that.

Android is the better platform here: Gboard's handwriting supports far more languages than Scribble, so a Samsung or other Android 14 tablet with a stylus may handle Bahasa where an iPad will not.

The 45-minute test that decides this feature. Open this page on three real tablets from the actual fleet and have three real users write three real Indonesian sentences in the pad in §01. Count the words that come back wrong.

Under ~10% wrong → Tier A ships as the default and handwriting costs nothing. Over ~30% → Tier B becomes the default for Bahasa and the vision-model transcription returns, but reached by a minority of notes rather than all of them, which changes the free-tier arithmetic entirely. In between → a per-note language toggle: id routes to Tier B, en to Tier A. Two lines of UI that turn an unpredictable failure into a stated trade.

05

Why Dexie, in four situations

if none of these were true, the entity adapter would be correct

Choosing Dexie is really choosing IndexedDB as the read model. That earns its place against four concrete situations, not against a preference.

What Dexie is not solving. It is a local database, not a sync engine, not a conflict resolver. Everything in §06 is code you write. That is the right trade here only because ThinkBoard has no concurrent editing — the group layer is leader-write, the individual layer is author-write, and highlight geometry is immutable. Nothing merges, so sync collapses from a distributed-systems problem into “send these rows in order, then diff a manifest”.

Lose that property — by making notes co-editable, say — and PowerSync becomes the plan rather than the escape hatch.

Why not PowerSync or ElectricSQL. Electric is a read-path sync engine — you would still write every line of ② yourself — and its vendor announced in August 2026 that it is joining Databricks with the cloud winding down. PowerSync is genuinely good and is the named escape hatch, but it replaces Dexie with SQLite-wasm, needs Postgres logical replication (whose known WAL-growth issue on idle Supabase instances describes a pilot project exactly), and its hardest-won feature is partial replication with causal consistency across many writers — a problem this design already removed.

The one question to answer first

Does Scribble produce usable Bahasa Indonesia on the fleet's actual iPads? Everything in §02–§04 hangs on it, the test costs 45 minutes, and the answer is the difference between a handwriting feature that costs nothing and one that costs a model call per note.
